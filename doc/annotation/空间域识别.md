# 离线空间域识别与可视化

空间域是根据 RNA 与空间位置计算的样本内无监督分组。`Domain 1` 等编号没有预设组织学
名称，不同样本中的同号域不表示同一种组织结构。该功能只面向二维 `full` Database。

## 方法与输入

`single_cell` 使用 BANKSY；`near_cellular`、`spot_level` 使用 GraphST。分流读取正式
`spatial_unit`，不依据 obs 数量重新分类，也不在资源不足时自动更换算法或抽样。
每个 `sample_id` 独立建图、预处理和聚类。计算保留源坐标精度，仅在生成浏览器点文件时转换为 float32。

首版读取 `rna.X` 中明确声明为 `counts` 的非负整数数据，按 observation ID 与顶层
`obs`、`obsm['spatial']` 对齐。缺少 RNA 和仅有标准化值但缺乏明确预处理依据的 Database
保留为待处理，不把其他模态自动当成 RNA。部分配对数据中无 RNA 的观测，以及 RNA 总量
为零的观测，保留在标签表和点位文件中，分别记录 `missing_rna`、`zero_counts`；网页将其
归为默认隐藏的灰色 `Not analyzed`。

移除全零与无变化特征；候选特征超过 3,000 时在 counts 上使用 Seurat v3 HVG，其余使用
全部候选特征。统一执行总量归一化至 10,000 和 `log1p`。BANKSY 使用官方组件 z-score；
GraphST 使用 `scale(zero_center=False, max_value=10)`，并明确标记已预处理，避免算法内部
重复归一化。没有足够观测或有效特征、非法计数、非法坐标、算法输出非有限值时生成失败报告。

Seurat v3 默认 LOESS span 为 0.3；仅在 `svddc failed`、`near singularities` 或
`reciprocal condition number` 数值错误时，依次重试 0.5、0.75、1.0。仍使用原始 counts、
相同 HVG 方法和 3,000 特征目标；全部失败则明确报错，不更换特征选择方法。每个样本的
`preprocessing.hvg_fit` 记录各次 span、错误与最终选择，发生重试时另有警告及任务日志。

| 项目 | 默认值 |
| --- | --- |
| BANKSY | `lambda=0.8`，空间邻居 30，`scaled_gaussian`，`max_m=1` |
| GraphST | 空间邻居 3，600 epochs，学习率 0.001，隐藏维度 64，CPU |
| 聚类 | 方法输出的 20 维 PCA，表达邻居 50，Leiden `resolution=1.0`，seed 42 |
| 特征与样本较小 | PCA 和邻居数按可用维度缩小 |
| 后处理 | 不搜索目标域数，不平滑标签，不做跨样本整合 |

GraphST 使用官方 `GraphST.train()` 返回的 `emb` 经 PCA 后直接执行 Leiden，跳过官方
`clustering()` 中以目标域数量搜索分辨率的分支。BANKSY 使用官方邻域/AGF 矩阵构建函数，
再进行 PCA 与 Leiden；不计算 UMAP。域编号按各簇最小 observation ID 稳定排序。

方法依据：[BANKSY 官方文档](https://prabhakarlab.github.io/Banksy/)、
[BANKSY Python](https://github.com/prabhakarlab/Banksy_py)、
[GraphST 官方实现](https://github.com/JinmiaoChenLab/GraphST)。

## 隔离环境与命令

算法包不安装进网站 `iscdc` 环境，也不改变 SingleR/RCTD 的 `iscdc-cell-annotation` 环境。
安装声明和精确 Python 包版本位于 `annotation/spatial_domain/`。锁文件指定 CPU PyTorch
下载源；生成时校验实际包版本，sidecar 保存锁文件 SHA-256。

锁定的 AnnData 0.11.4 通过离线适配器补充 HDF5 `null` 0.1.0 读取器，按 AnnData 0.12 的
语义把 null dataspace 还原为 `None`。仅注册缺失的该类型读取器，未知编码仍报错；不升级
算法包、不删除元数据、不重写源 H5MU。报告和适配器源码摘要记录这一读取兼容行为。

在项目根目录创建环境，然后激活：

```bash
(cd annotation/spatial_domain && conda env create -f environment.yml)
conda activate iscdc-spatial-domain

PYTHONPATH=src python -m iscdc.spatial_domain_annotation \
  generate-spatial-domain-visualization DATASET_ID \
  --config assets/spatial_domain/defaults.yaml \
  --output-root temp/spatial_domain_run/sidecars
```

也可以使用名为 `iscdc-spatial-domain` 的独立 Python 3.11 virtualenv 安装相同锁文件；运行
其 Python 可执行文件即可。`--force` 表示新建不可变 generation，并原子更新最新状态，
不会覆盖旧 generation 或修改源 H5MU。已有任何状态文件时默认拒绝覆盖。

输入资格和结果审计是只读操作，可在网站环境执行：

```bash
conda activate iscdc
PYTHONPATH=src python -m iscdc.cli audit-spatial-domain-visualizations --all \
  --output-root temp/spatial_domain_run/sidecars
```

主 CLI 同样提供 `generate-spatial-domain-visualization`；计算时仍须使用隔离环境。
审计不会自动触发计算。

配置支持全局默认值、数据集参数和样本参数，优先级依次提高。`threads`、内存预算和坐标
朝向只能在全局或数据集层设置。方法由分辨率决定，不能在 YAML 中覆盖：

```yaml
defaults:
  resolution: 1.0
  threads: 40
  memory_budget_gb: 128
datasets:
  example_dataset:
    parameters:
      banksy_lambda: 0.8
    samples:
      sample_1:
        resolution: 0.8
```

默认最多 40 个 CPU 线程、128 GiB 任务内存；CPU affinity 会额外为当前可用核保留至少
8 个逻辑核（不足时最低使用 1 核），进程 nice 值增加 5。GraphST 的小矩阵训练默认最多
8 个线程，避免线程调度开销。BLAS、OpenMP、Numba 同时限流。同一用户的空间域命令通过
临时目录中的全局锁串行计算，不同输出目录也不会叠加计算线程。并行 supervisor 则持有该锁，
向子进程传递资源租约并统一执行总预算；独立命令不能与它叠加运行。另有数据集锁，防止并发覆盖。

子进程启动前设置 `PYTHONHASHSEED`，并固定 Python、NumPy、PyTorch、PCA 与 Leiden 的随机种子；
报告保存适配器源码摘要及预处理、方法特征、PCA、邻居图的中间摘要，便于定位跨进程重放差异。
稀疏矩阵摘要直接处理 CSR 数组，避免为校验构建稠密邻接矩阵。

计算前估计上游稠密矩阵、训练与 PCA 的峰值空间，并在可用内存中保留 8 GiB；运行时父进程
监控子进程和后代的 RSS，超过配置预算则终止并记录失败。GraphST 存在平方级矩阵分配，
因此低分辨率分类不保证任意大规模数据都可计算。报告记录耗时、峰值 RSS、CPU 时间及 affinity。

## 结果文件与页面

默认根目录为 `data/spatial_domain_visualizations/`，通过
`ISCDC_SPATIAL_DOMAIN_VISUALIZATION_ROOT` 可改用隔离目录。每个数据集的 `status.json`
指向最新成功 generation 或失败报告；成功 generation 包含：

- `manifest.json`：来源文件摘要、观测顺序摘要、分辨率、坐标声明、算法与环境指纹。
- `report.json`：每个样本的实际参数、特征列表与摘要、覆盖数、域数量/大小、空间连通分量和资源使用。
- `assignments.tsv.gz`：按顶层 observation 顺序保存 ID、sample ID、domain ID 和未分析原因。
- `points/`：按样本保存 identity、gzip、Brotli 三种一致的二进制点数据。

二进制格式使用独立 `ISCDCSD\0` magic 和
`application/vnd.iscdc.spatial-domain-points` MIME，布局沿用既有 32 字节头、float32 x/y
与 uint16 类别数组，不包含置信度。内部 GET/HEAD 接口为
`/databases/{dataset_id}/spatial-domain-visualization/{generation_id}/{sample_key}`。
启动时校验文件摘要、标签顺序、类别计数、QC 计数和来源绑定，网页请求不读取大型 H5MU。
损坏、缺失、最新失败或过期结果只使对应模式不可用。

页面复用一个画布，在 `Cell types` 与 `Spatial domains` 间切换。默认优先细胞类型，只有
空间域时直接显示空间域；切换保留样本、位置与缩放，图例选择按模式和样本独立保存。
两种模式统一采用初始视图的坐标朝向，不因切换上下翻转。空间域方法说明没有细胞类型
参考库或置信度；hover 显示域标签与原始坐标。原细胞类型的 `Unannotated` 行为保持不变。

技术校验通过不等同于组织学准确性验证。单域结果会记录警告；没有人为保证某个域数、
最小域比例或连通分量阈值，也不会用细胞类型标签作为空间域真值。

## 全量后台队列

`iscdc.spatial_domain_batch` 支持冻结计划、逐数据集日志、每分钟心跳、动态 ETA 和断点恢复。
在空间域环境中先准备一个全新运行目录，`--python` 指向持久目录中的隔离 Python：

```bash
conda activate iscdc-spatial-domain
PYTHONPATH=src python -m iscdc.spatial_domain_batch prepare \
  --run-root temp/spatial_domain_full_run \
  --python "$CONDA_PREFIX/bin/python" \
  --reuse-root temp/spatial_domain_20260919/final/sidecars
```

`--reuse-root` 可省略；只有来源、算法源码、锁文件和全部实际参数一致的成功结果才复用。
准备阶段只读备份 catalogue，将源码、配置、锁文件冻结到运行目录的 `code/`，并记录文件
摘要。输入不合格者标为 `skipped`，保留原因。待计算数据按预计工作量从小到大排序，较早获得
吞吐量校准；不会抽样或自动改变算法参数。

从冻结源码启动，使用 `nohup` 和独立 session，使任务不依赖终端或 SSH 连接：

```bash
run_root="$PWD/temp/spatial_domain_full_run"
PYTHONPATH="$run_root/code/src" nohup setsid python -u -m iscdc.spatial_domain_batch run \
  --run-root "$run_root" --heartbeat-seconds 60 \
  </dev/null >>"$run_root/supervisor.log" 2>&1 &
```

实际 supervisor PID 和 session ID 会写入 `progress.json`。每个推理子任务也有独立 session，
supervisor 忽略 SIGHUP。进程自然结束父 shell 后仍可运行；主机重启不属于此保证。计算仍采用
40 线程、128 GiB 预算和全局串行锁。环境和运行目录应保留，计算期间不要修改其中的冻结文件。

运行目录包括：

- `plan.json`：固定清单、输入快照及源码摘要。
- `progress.json`：原子更新的完整状态、当前任务、成功/失败/跳过数量和剩余时间估计。
- `events.jsonl`、`supervisor.log`：带 UTC 时间戳的开始、结束、每分钟心跳与总体进度。
- `logs/<序号>_<dataset_id>.log`：算法原始 stdout/stderr、GraphST epochs、开始/结束及退出码。
- `sidecars/`：成功 generation 或详细失败报告。

心跳包含当前任务 elapsed、进程树 RSS/峰值 RSS、CPU 时间、线程数和最新一行算法输出。
心跳峰值为采样值；成功 generation 的报告另含工作进程自身记录的峰值 RSS。
ETA 依据已成功任务的算法类别和输入规模动态校准，并逐次更新；大规模、多个样本或资源
预检失败的任务会使早期估计波动。`completed` 包括已处理的失败和跳过项，`successful` 才是
生成成功与复用的数量，`eligible_total` 排除缺少合格输入的项目。队列 `complete` 表示遍历
结束，不代表每个任务都成功。

查看日志和简明状态：

```bash
tail -f "$run_root/supervisor.log"
python -c 'import json,sys; s=json.load(open(sys.argv[1])); print(json.dumps({k:s.get(k) for k in ("state","updated_at","current","progress")},ensure_ascii=False,indent=2))' "$run_root/progress.json"
```

正常停止时对 `progress.json` 中的 `supervisor_pid` 发送 SIGTERM；它会终止当前任务的整个
进程组并保存 `interrupted` 状态。恢复时重复相同 `run` 命令：成功项不重算，已记录失败项保留，
中断项重新开始；若子任务已经原子发布成功则直接恢复该结果。运行目录锁会拒绝第二个 supervisor。
全量结果仍在独立目录，页面发布和服务重启另行执行。

首次后台全量任务的目录和启动核验见[2026-09-19 全量后台运行记录](空间域识别全量后台运行_2026-09-19.md)。

## 并行续跑

`iscdc.spatial_domain_parallel` 从已正常停止的队列创建新的冻结运行目录。默认最多 8 个任务，
合计 64 个逻辑核、192 GiB 内存预算，另保留至少 16 GiB 可用系统内存。启动时验证至少保留
8 个可用逻辑核；本机 80 核配置实际保留 16 核。GraphST 每项 8 核，BANKSY 每项 16 核，
以互不重叠的 CPU affinity 执行，并保留 nice +5。

先对旧 supervisor 发送 SIGTERM，确认 `progress.json` 为 `interrupted` 后，在空间域隔离环境运行：

```bash
PYTHONPATH=src python -m iscdc.spatial_domain_parallel continue \
  --previous-run temp/spatial_domain_full_run \
  --run-root temp/spatial_domain_parallel_run \
  --max-workers 8 --cpu-budget 64 --memory-gb 192

run_root="$PWD/temp/spatial_domain_parallel_run"
PYTHONPATH="$run_root/code/src" nohup setsid python -u -m iscdc.spatial_domain_parallel run \
  --run-root "$run_root" --heartbeat-seconds 60 \
  </dev/null >>"$run_root/supervisor.log" 2>&1 &
```

续跑保留原 catalogue 快照、原输入路径、成功结果、失败记录和日志；中断项回到待执行状态。
修复后可在 `continue` 命令中增加 `--retry-failed`，将失败项重新排队；旧失败报告、日志和
`attempt_history` 均保留，并在资源预算内优先执行这些重试项。默认不重试失败项。新目录冻结
当前适配器代码，禁止原地修改活动快照。
已完成结果保留其实际生成代码与环境的原始 provenance，不伪装成新调度器重新计算的结果。
新任务的每份资源配置保存于 `job_configs/`，只覆盖 CPU 线程和内存预算，RNA 预处理、方法、
随机种子及聚类参数沿用原配置。不同线程数可能引起浮点计算差异，因此新结果仍记录完整实际参数。

每项预留内存为原预检估计乘以 1.15 再加 1 GiB、向上取整；调度同时约束 CPU、任务槽和
内存总额，并优先用可容纳的较轻任务填补大任务旁的空闲 CPU。大任务运行时实际并发可能
低于 8；早期 RSS 小不代表后续构图/PCA 内存也小。超出总预算的单项会明确失败，等待系统
内存时则保留待执行状态。每秒监控进程树 RSS，单项超限、总额超限或系统可用内存低于保留量
会终止相应任务并记录原因。

supervisor 独占全局资源锁，工作进程继承锁描述符作为资源租约；子进程不能解除 supervisor
的锁。正常停止会终止全部活动进程组，再保存中断状态并释放锁。恢复时使用相同 `run` 命令，
已成功项不重算，既有失败项保留，不自动修改参数重试。

`progress.json` 新增 `active` 数组和 `resource_usage`：逐项记录 PID、CPU 集合、预留内存、
实际 RSS、CPU 时间、运行时长与最新日志；总览记录已分配 CPU、预留/实际内存及主机可用内存。
ETA 按 CPU/内存约束模拟任务排布，不能简单将串行耗时除以任务数。BANKSY 另以相邻已完成
规模为锚点，使用 observation 数的 1.5 次方估计大型 Leiden 图的非线性成本。超出原估计的
活动任务列入 `eta_overdue_jobs`，预计剩余时间至少为已运行时长的一半；活动 BANKSY 也作为
尚未完成的耗时下界参与大型任务估计。该启发式估计不是完成时限，长尾任务仍可能更慢。
日志位置和一分钟心跳约定保持一致。

## 分析完成后一键发布

用户在全量分析完成后执行以下命令，即授权本次正式 sidecar 发布和测试网站重启：

```bash
bash annotation/spatial_domain/publish_completed.sh
```

脚本支持从任意工作目录以绝对路径调用，自动激活网站 `iscdc` 环境。默认读取
`temp/spatial_domain_full_latest.json` 指向的最新批次，发布到
`data/spatial_domain_visualizations/`，调用现有 `deploy_test.sh` 管理的网站。
网站应已由该部署脚本启动且健康；脚本在停机前检查这一前提。使用已构建并纳入版本控制的
前端 bundle，不需要安装算法包、Node 依赖或重新运行推断。

执行流程如下：

1. 要求批次 `state=complete` 且任务仅包含 `success`、`reused`、`skipped`，取得队列及
   全局资源锁。任何失败、未完成任务或另一计算进程持锁都会阻止发布。
2. 验证冻结 catalogue/代码摘要、任务清单与当前正式 Database 集合及科学元数据一致；
   逐项重新计算源 H5MU SHA-256，并完整校验 sidecar 的标签、点位、覆盖、QC 和来源。
   `skipped` 必须有与当前输入资格一致的原因；不会将其当作成功结果，也不会伪造标签。
3. 在正式目录同一文件系统的 `.spatial_domain_visualizations-releases/<批次>/sidecars/`
   复制旧结果并合入新 generation，保留旧 generation 及本次范围外的原有文件，再次校验
   暂存结果。相同 generation ID 的不同内容视为冲突，停止发布。
4. 再次确认来源与 catalogue 未改变后，停止测试网站，将正式目录切换为新 release 的
   符号链接并启动网站。首次遇到实体正式目录时，将其原样保存在 release 的 `previous/`；
   若原目录是 release 链接，则记录原链接。启动默认最多等待 600 秒。
5. 通过本机 HTTP 检查健康状态、前端 bundle 内容、每个已发布 Database 的详情页
   generation/样本，以及每个样本点位文件的 MIME、长度和 SHA-256。
6. 启动或发布后验证失败、可捕获中断时恢复旧目录/指针并重新启动原结果的网站。
   新旧 release、原计算结果和失败证据均保留，不自动清理。

这一步发布独立可视化结果，不向正式 catalogue 添加记录或改写 H5MU。校验验证的是计算、
来源及传输完整性，不替代组织学质量评估。全库源摘要检查会顺序读取原始 H5MU，期间网站
继续运行；只有最终切换和重新加载阶段暂停服务。

仅检查或选择指定批次：

```bash
bash annotation/spatial_domain/publish_completed.sh --check-only
bash annotation/spatial_domain/publish_completed.sh --run-root temp/spatial_domain_repaired_20260919T141044Z
```

未完成时 `--check-only` 同样返回非零退出码，但不发布或重启。脚本不等待正在进行的分析，
也不自动忽略失败项；修复并完成续跑后，再执行同一命令。重复执行保留历史版本。

### 先发布已完成结果

后台尚在计算时，可显式选择部分发布：

```bash
bash annotation/spatial_domain/publish_completed.sh --completed-only
```

该模式在开始时固定 `success`/`reused` 清单，仅校验并发布这些不可变 generation。
`pending`、`running`、`interrupted`、`failed` 记入 `deferred`，不复制这些任务的临时结果或
失败状态，也不删除它们原有的正式结果。正常输入资格跳过仍单列为 `skipped`。成功清单为空、
成功结果损坏或来源变化仍会阻止发布，不能通过此选项绕过校验。

部分发布不占用 supervisor 和计算资源锁，不停止计算任务；改为独立的目标目录发布锁，
以及已选成功数据集的 generation 锁，防止两个发布进程同时切换或选定结果被改写。
审计、暂存校验、网站重启、HTTP 验证和失败回滚与完整发布相同。运行期间新完成的任务
留给下一次调用；再次运行同一命令即可补充。可组合 `--completed-only --check-only` 仅检查。
`audit.json` 和 `published.json` 记录部分发布模式、进度快照时间及 `deferred` 状态/原因。

首次部分发布的数量、服务检查和运行路径见[2026-09-20 发布记录](空间域识别发布记录_2026-09-20.md)。

每次调用的日志位于 `temp/spatial_domain_publication_<时间>-<随机后缀>/`：

- `events.jsonl`：阶段、逐数据集进度、失败原因及回滚状态，同步打印到终端。
- `audit.json`：逐项源签名、选定 generation、manifest、当前目录绑定及跳过原因。
- `service.log`：部署脚本完整输出。
- `published.json`：仅在发布和 HTTP 验证均成功后生成，记录正式路径、release 和数量。

release 中的 `transaction.json` 保存切换状态和旧目录/链接位置。自动回滚失败会明确记录
`rollback_failed` 并返回失败；强制 SIGKILL 或断电无法运行回滚代码，此时应按该事务记录恢复
目录和服务，不能把缺少 `published.json` 的运行当作成功。不应在发布过程中手动修改正式指针。

沿用部署脚本的 `ISCDC_DEPLOY_PORT`、`ISCDC_DEPLOY_SESSION`、`ISCDC_DATABASE_PATH`、
`ISCDC_DATA_ROOT` 等环境配置；自定义结果根目录使用 `ISCDC_SPATIAL_DOMAIN_VISUALIZATION_ROOT`，
它会显式传给 tmux 中的网站进程，避免复用旧 tmux 环境时加载错误目录。Conda 安装位置不同
时，用 `ISCDC_CONDA_SH` 指定 `etc/profile.d/conda.sh`。
