sidecar 生成任务。本文关注可复用的方法学、失败诊断、资源调度和审计经验；每一轮的完整参数、
指标和终态仍以
[`assets/cell_type_annotation/iteration_history.yaml`](../../assets/cell_type_annotation/iteration_history.yaml)

最终全量审计结果为：

## 2. 最重要的原则

### 2.1 不把“全部成功”理解成强制赋予标签

发布成功表示方法、校准、reference QC、目标 QC、来源校验和和产物完整性均通过，并不表示
每个观察都必须得到一个生物类型。`Mixed` 和 `Uncertain` 是必要的推断状态：

- `Mixed` 表示 bin/spot 中没有单一类型占据足够优势；
- `Uncertain` 表示现有 RNA 证据不足以可靠发布一个生物类型；
- 两者都不是 Cell Ontology 类型，不应伪造 CL ID；
- 降低阈值以消灭 `Mixed` 或 `Uncertain` 会把不确定性隐藏成看似确定的错误标签。

因此，科学质量失败可以作为一次运行的有效终态；修复必须针对失败原因，而不能以“让 QC
变绿”为目标倒推阈值。

### 2.2 reference QC 与目标数据 QC 必须分开

本次反复出现两类完全不同的问题：

1. reference 自身不可辨识，例如 balanced accuracy、macro-F1 或 ECE 不合格；
2. reference 通过，但其校准分布不能覆盖真实 target，例如真实 spot 更复杂，或 Xenium 与
   scRNA-seq 存在平台分数偏移。

第一类问题应修 reference、标签体系或 holdout；第二类问题应修目标分布建模或校准设计。
不能用降低 reference QC 门槛去掩盖第一类问题，也不能仅因 reference 指标合格就断言目标
结果可靠。

### 2.3 先保存诊断证据，再修改配置

baseline 失败报告没有保留 target confidence、score、weight、margin 和 entropy 的分布，
导致无法区分“真实混合”“低置信度外推”和“算法未收敛”。之后在每个 scientific failure 中
保留了有界摘要：

- confidence、best score、delta 的分位数；
- RCTD top/second weight、margin、entropy、effective types 的分位数；
- 各种 `Uncertain` 原因的计数；
- reference QC、校准 ID 和实际应用的阈值。

这一步把参数调整从猜测变成了可验证的假设。一次失败应首先回答“哪个 gate 失败、多少观察
由哪个条件触发、目标分布位于校准分布的什么位置”，然后才进入下一轮。

## 3. RCTD 任务的主要经验

### 3.1 单细胞式 dominant 阈值不适合真实空间 bin/spot

baseline 使用 `top_weight >= 0.65`、`margin >= 0.15` 和固定 0.5 calibrated confidence，
在若干组织中将几乎所有 spot 判为 `Mixed` 或 73%–100% 判为 `Uncertain`。真实空间观察通常
包含多个细胞，不能沿用接近单细胞纯度的门槛。

第一轮修复采用的诊断性 target 阈值为：

- `uncertain_min_confidence: 0.20`
- `mixed_min_top_weight: 0.35`
- `mixed_min_delta: 0.05`
- `mixed_max_entropy: 0.95`

这些值修复了 lymph node、P21/P22 brain、spleen 和 thymus 等目标，但它们不是新的全局常数。
正确做法是用与目标分辨率和混合复杂度一致的 pseudo-spot 校准来证明阈值适用。

### 3.2 pseudo-spot 必须覆盖真实混合复杂度

E13 的失败是最清晰的例子。旧校准仅模拟 70/30 的两类型混合，而真实 bin 的中位有效类型数
为 5.24、中位 top weight 为 0.316；即使 reference QC 通过，86.94% 仍被判为
`Uncertain`。

修复采用：

- 五种类型参与每个 mixed pseudo-spot；
- dominant fraction 0.40；
- 每类型 60 个 pure pseudo-spots；
- 360 个 mixed pseudo-spots；
- logistic-fit、isotonic recalibration 和 final evaluation 三个互不重叠的分区。

结果证明问题在校准总体失配，而不是需要降低 `uncertain_min_confidence`。新的校准把 E13
`Uncertain` 降至 14.80%，同时保留 46.37% 的真实 `Mixed`。

### 3.3 校准指标必须在与用途一致的总体上计算

胃肠 reference 曾出现 pure-only ECE 0.2167，但 calibrator 的实际用途是判断 pure 和 mixed
pseudo-spots 的 dominant-type reliability。把 pure-only ECE 当作唯一发布 gate，评估总体与
校准用途不一致。

最终设计是：

- pure pseudo-spots 用于 balanced accuracy 和 macro-F1；
- 完整 pure-plus-mixed 独立评估集用于 dominant-reliability ECE；
- pure-only ECE 继续作为诊断指标保存，但不替代用途一致的主 gate。

调整评估定义后，总体 ECE 为 0.0744，且 pure-only ECE 0.2167 仍被如实保留。指标选择必须
在建模前按预期用途定义，不能在看到结果后选择更容易通过的总体。

### 3.4 同一 holdout 不应同时拟合和证明校准有效

小规模 pseudo-spot 集会让 accuracy 和 ECE 高度不稳定。GBM 初始只有 48 个 pure evaluation
pseudo-spots，胃肠 reference 只有 24 个。扩大评估集并采用三路独立拆分后，GBM 达到
BA 0.8583、macro-F1 0.8558、ECE 0.0625。

推荐固定三路职责：

1. model-fit：拟合 logistic reliability；
2. recalibration：拟合 isotonic correction；
3. evaluation：只用于最终 BA、macro-F1 和 ECE 报告。

任何一个 evaluation observation 都不应参与前两步。

## 4. reference 选择与标签体系

### 4.1 组织、疾病和发育阶段匹配优先于 reference 规模

MISAR E13/E15/E18 最初使用 developing-cerebellum proxy，但 whole-brain target 与该组织代理
并不匹配。替换为阶段匹配的 control thalamus reference 后，E15 和 E18 分别达到：

- E15：BA 0.875、macro-F1 0.851、ECE 0.028；
- E18：BA 0.9636、macro-F1 0.9621、ECE 0.0196。

“细胞更多、类型更多”不自动等于更好的 reference。组织、疾病、阶段、物种、gene key 和
独立 donor 证据的匹配更重要。胃肠任务中，唯一更宽的 26-type 候选是 pooled single-donor
来源，因此不能替代满足 donor-holdout 要求的多供体来源。

### 4.2 父子标签重叠会造成不可辨识，校准无法修复

多个 reference 同时保留了 generic parent 与可辨识 child，例如：

- generic large-intestine epithelial / secretory parent 与其子类型；
- generic neuron / ependymal parent 与更具体的神经或室管膜子类型；
- generic lymphocyte / renal epithelial parent 与具体免疫、肾细胞类型。

此时 isotonic calibration 只能校正概率可靠性，不能让表达上不可区分的父子类别变得可辨识。
按明确规则裁剪重叠 parent 后，E15、胃肠和 kidney reference 的 accuracy/F1 才得到实质改善。

裁剪必须保留原始 CL ID 与规则说明，并基于“父类与已保留子类重叠”或“该组织不适用”等可
审计理由，不能因为某个类别难预测就任意删除。

### 4.3 holdout donor 的组成必须能评估预期类型

kidney 的旧 holdout 几乎只覆盖免疫类型，无法证明肾实质、基质和血管类型的泛化能力。
换用可独立评估六种 renal、stromal、vascular 和 immune 类型的 donor，并去除不适用或
层级重叠标签后，reference 达到 BA 1.0、macro-F1 1.0、ECE 0.0032。

胃肠任务也显示，所谓“组成更均衡”的替代 donor 反而把 BA/F1 降到 0.5333/0.4696。
因此选择 holdout 时既要看类型覆盖，也必须用真正独立的最终评估验证，不能只根据元数据
表面平衡度判断。

## 5. Xenium / SingleR 的跨平台经验

Xenium reference 已限制到 402 个与靶向 panel 共享的基因，并通过 donor-holdout reference
gate，但第一轮仍有 80.50% `Uncertain`。诊断显示：

- 368,025 个细胞低于 absolute best-score cutoff；
- 46,757 个细胞 delta 低于阈值；
- 只有 82 个细胞缺少 `pruned.labels`；
- target best-score 中位数为 0.4246，而 scRNA-seq holdout cutoff 为 0.5119。

因此主要问题不是缺少共同基因或 SingleR pruning，而是 scRNA-seq 与 Xenium 的绝对分数
分布偏移。直接手工降低 0.5119 会失去可靠性依据。

最终修复流程为：

1. 从 Xenium 稀疏 CSR 的 `data` 和 `indptr` 计算每细胞 RNA panel counts 深度，不构造
   465,534 × 405 的稠密矩阵；
2. 保存目标深度分位数及确定性正深度样本；目标中位深度为 70，零计数细胞为 306；
3. 对有真实标签的独立 donor holdout 按目标深度分布进行确定性稀疏下采样；
4. 保持完整 training reference，不使用目标标签；
5. 在深度匹配后的 holdout 上重新拟合并独立评估 SingleR reliability。

reference v2 获得 BA 0.5580、macro-F1 0.5585、ECE 0.0143，新 score cutoff 0.4324、delta
cutoff 0.0026。阈值变化来自有标签 holdout 的目标深度模拟，而不是人工修改 target gate。

该结果应保守解释：BA/F1 仅略高于预设 0.55 门槛，最终 `Uncertain` 也接近 60% 上限。
这不是高置信度全覆盖注释；sidecar 必须继续展示逐细胞 confidence 和 `Uncertain`，且不能把
推断标签写回 canonical metadata。protein 仅用于独立 QC，不覆盖 RNA 产生的标签。

## 6. 资源调度经验

### 6.1 声明 worker 数是上限，不是实际占用

本次观测到：

- baseline 中，3 cores/job 比 12 cores/job 更有利于批量主机利用率；
- 8 个 4-core job 的探测达到约 30.3 个逻辑核，但运行被中止，没有产生科学结果；
- 7 个 5-core RCTD job 声明 35 核，采样实际最高约 21 核；
- Xenium 从 12 workers 提高到 30 workers 后，采样峰值仍约 6.36 个逻辑核、RSS 5.14 GiB。

SingleR/RCTD 的不同阶段有串行、I/O、fork 和汇总部分，worker 数不能直接等同于持续 CPU。
调度应同时记录 declared cores 与实际 `%CPU/100`、RSS；若单任务长期未占满，应优先增加
相互独立的任务数，而不是继续增加单任务 worker。

### 6.2 BLAS 线程限制必须在启动 R 之前设置

在 R package 加载后才设置 OMP/BLAS 环境变量过晚，可能出现隐藏线程池和超额占用。应由
Python parent process 在启动 `Rscript` 前统一设置：

```text
OMP_NUM_THREADS=1
OMP_THREAD_LIMIT=1
OPENBLAS_NUM_THREADS=1
MKL_NUM_THREADS=1
GOTO_NUM_THREADS=1
BLIS_NUM_THREADS=1
RCPP_PARALLEL_NUM_THREADS=1
```

算法内部的显式 worker 由运行配置单独控制。

### 6.3 reference 下载可以与独立注释并行，但发布仍需原子化

reference 下载主要受远端 I/O 限制，可与不依赖该 reference 的 annotation job 并行。
reference build 本身应保持受控，并限制 TileDB 隐藏线程池。Census 曾出现 transient SSL EOF；
三次有界重试加独立 staging 可以恢复，而失败 staging 不应覆盖已发布 reference。

所有最终产物都必须在目标 NFS 根目录内 staging 后原子切换。被中断的 4-core probe 没有发布
任何 generation，旧终态仍保持权威，证明该失败语义有效。

## 7. 推荐的迭代诊断顺序

以后遇到 scientific failure，建议严格按以下顺序处理：

1. **确认失败类型**：区分 framework failure、reference QC failure 和 target QC failure。
2. **确认输入不变**：核对 source SHA、obs 顺序、二维坐标、gene key 和稀疏 raw counts。
3. **查看 reference gate**：共同基因、BA、macro-F1、ECE、holdout donor/type coverage。
4. **查看 target 分布**：confidence、best score、delta、top weights、entropy、effective types
   及每种拒绝原因计数。
5. **形成一个可证伪假设**：例如层级标签重叠、stage mismatch、混合复杂度不足或平台深度偏移。
6. **只改变与假设对应的因素**：不要同时更换 reference、降低 QC gate 和修改 target threshold。
7. **使用独立评估**：拟合、再校准和最终评估不得复用观察；保存 seed 和样本设计。
8. **原子发布或失败撤下**：新失败必须使旧成功不再被网站索引。
9. **记录该轮经验**：保存修改、指标、终态、资源样本，以及哪些尝试无效。
10. **全量复审**：所有目标完成后执行 `audit-cell-type-visualizations --all`，不能只检查最后
    修复的数据集。

## 8. 不应重复的做法

- 不要把固定 confidence、weight 或 margin 阈值无条件复制到不同组织和空间分辨率。
- 不要因为 isotonic ECE 改善就认为父子标签不可辨识已经解决。
- 不要使用参与 calibration 的 observation 报告最终 ECE。
- 不要使用与 calibrator 用途不同的总体作为唯一 ECE gate。
- 不要用 pooled single-donor reference 冒充 donor-level holdout 泛化证据。
- 不要手工降低绝对 SingleR score cutoff 来补偿平台偏移；应在有标签 holdout 上模拟目标域。
- 不要 densify 大型空间矩阵；深度统计、RNA exchange 和 reference I/O 均应保持稀疏。
- 不要让 protein、ATAC 或 histone 信号覆盖 RNA 产生的标签。
- 不要把推断标签写回正式 `.h5mu`、catalogue schema 或公共 JSON。
- 不要根据 worker 配额推断实际 CPU 使用；必须监测真实进程。
- 不要在 framework failure 或进程中断时发布半成品。

## 9. 每个任务必须保留的证据

每个成功 generation 至少应包含：

- source `.h5mu` SHA-256、observation count 和 obs 顺序摘要；
- 注释方法、完整运行参数和环境锁摘要；
- reference ID、版本、文件 checksum、来源版本、license 和筛选条件；
- SingleR 全部分数和 `pruned.labels`，或 RCTD 完整 weights、top-2、margin、entropy 与收敛信息；
- 校准 ID、设计参数、阈值和最终 QC；
- `Mixed`/`Uncertain` 计数及置信度；
- generation、report、inference 和点位文件的 checksum。

每个 scientific failure 至少应保存相同的输入、方法、参数、reference 和 QC gate，再加上有界的
target 分布诊断与明确失败原因。`status.json` 必须只指向最新成功 generation 或最新失败报告。

最终 provenance 审计应验证计划参数与 manifest 参数逐项相等，而不只是检查字段存在。本次
最终审计实现了 35/35 精确参数匹配和 32/32 完整推断 reference 记录。

## 10. 可复用的完成标准

一次 catalogue-wide 注释任务只有同时满足以下条件才算完成：

- 每个目标都有当前成功 generation；
- reference 和 target QC 均通过预先声明的 gate；
- `Mixed`/`Uncertain` 未被伪装成生物类型；
- 最新 source SHA、obs 顺序、manifest、report、inference 和所有点位文件均通过审计；
- 方法、参数、reference 和环境信息可由产物独立追溯；
- 原始 `.h5mu` checksum 未改变；
- 全量 audit、Python/R annotation tests、后端完整 pytest 和 Ruff 均通过。

本次最终证据为：全量 audit 35 success、Python 后端 206 tests passed、annotation Python
3 tests passed、R contracts 2 passed、Ruff passed、YAML parse passed。

## 2026-09-20：Uncertain 默认隐藏

细胞类型图例中的精确标签 `Uncertain` 与 `Unannotated` 均默认不勾选，对应点位以零半径隐藏。
用户可单独勾选或使用 `Select all` 恢复显示；`Mixed`、`Unlabeled` 和其他类别仍默认显示。
选择状态按模式和样本保留。该调整仅影响浏览器展示，不改变预测状态、置信度或 sidecar 内容。

## 2026-09-19：独立的空间域可视化

空间域识别与细胞类型推断分别保存结果，在详情页同一画布中通过始终可见的模式按钮切换。
默认保留有效的细胞类型注释；缺失或过期结果禁用相应按钮并提示不可用，避免误认为被覆盖。
空间域按分辨率使用 BANKSY 或 GraphST，见[空间域识别](空间域识别.md)。GraphST/PyTorch 放在独立的
`iscdc-spatial-domain` 环境，不加入既有 SingleR/RCTD 环境。默认串行计算，最多 40 个 CPU
线程、128 GiB 内存，保留系统资源并监控实际 RSS。域编号只表示当前样本内的无监督分组，
不得转换为 canonical cell type，也不复用细胞类型 reference/QC 阈值或置信度。
`Not analyzed` 仅用于空间域模式中的缺 RNA/全零观测；既有 cell type 的 `Unannotated`
语义和默认隐藏规则不变。首批代表数据验证采用隔离目录，不等同于全库上线。

全量空间域计算使用独立后台 supervisor，冻结 catalogue、源码、配置及环境锁文件，逐任务
记录结果并每分钟更新进度和 ETA。成功结果可校验复用，单任务失败继续队列；SIGTERM 保存
中断状态，恢复时不重算已完成结果。断开 SSH 不影响独立 session 中的任务，实际操作见
[全量后台队列](空间域识别.md#全量后台队列)。

经授权提高并发后，空间域并行 supervisor 在全局资源锁内统一分配 CPU 和内存：默认最多
8 项、64 个逻辑核、192 GiB 总预留内存，GraphST 每项 8 核、BANKSY 每项 16 核，CPU 集合
互不重叠。大任务依据预检估计预留内存，不能只按实际早期 RSS 同时启动全部大任务。停止
串行队列后从新的冻结目录续跑，保留已成功结果及其原始 provenance，不修改算法数值参数；
新任务记录各自线程和内存预算。具体边界见[并行续跑](空间域识别.md#并行续跑)。

全量运行还暴露两类兼容/数值问题：新版 AnnData 写出的 HDF5 `null` 0.1.0 元数据，需要在
锁定的旧版算法环境补充只读兼容读取器；稀疏 counts 的 Seurat v3 局部拟合可能奇异，使用
0.3、0.5、0.75、1.0 的固定 span 序列，仅对已知数值错误重试，并保存每次错误、实际 span
和警告。不能将这两类失败归因于坏数据，也不应删除元数据或静默换算法。`continue --retry-failed`
保留旧失败证据并重新排队。大型 BANKSY 的 Leiden 耗时不能只按 obs×genes 线性外推，ETA
现加入 obs 的非线性成本与未完成任务下界；仍需结合 `eta_overdue_jobs` 判断估计可信度。

分析完成后的空间域发布由 `annotation/spatial_domain/publish_completed.sh` 串联：默认要求
所有具备输入资格的任务成功，重新核验源摘要和 sidecar，再保留旧版本、切换正式结果目录、
重启并逐项验证 HTTP 页面与点位。启动或验证失败时回滚，不写 catalogue/H5MU。仅检查使用
`--check-only`；调用脚本执行发布是用户明确的发布/重启操作，分析队列本身仍不会自动发布。
部署到已有 tmux server 时，应显式传递空间域目录环境变量，不能假设当前 shell 的新变量会
自动进入既有 tmux 环境。详见[一键发布](空间域识别.md#分析完成后一键发布)。

需要先展示已完成结果时，可显式使用 `--completed-only`：固定开始时的成功 generation 清单，
以独立发布锁及选定数据集锁保护复制/切换，不占用计算队列的全局锁；其他任务记录为
`deferred` 并保留其原有正式结果。随后完成的任务在下一次调用补入，校验与回滚不降级。

## SpatialGLUE 双／三模态空间域

RNA/SpatialGLUE 显示颜色的重合匹配必须提前离线完成。启动时逐数据集读取 assignment
并求解会累积到全库启动超时；单样本耗时和 fixture 测试不能替代全库 HTTP 就绪测量。
在网站 `iscdc` 环境运行 `python -m iscdc.cli generate-spatial-domain-colors`（`PYTHONPATH=src`），
将 generation/manifest 绑定的映射原子保存到 `catalog.db` 同目录的
`spatial_domain_colors.json`。网站只读取固定映射；缺失或无法读取时保留原色，绝不在线
补算。启动默认所有校验和测试已完成，不再进行摘要、来源、点位解压或 QC 校验；
映射与当前 generation 的一致性由离线准备负责。发布新域结果后显式刷新配色表，不修改推断标签或点文件。

SpatialGLUE 在独立 `iscdc-spatial-domain-gpu` 环境使用 CUDA 训练，使用 igraph Leiden
聚类，与原 BANKSY/GraphST RNA 结果独立保存。网页三种视图分别为细胞类型、RNA 空间域和
SpatialGLUE 空间域；共享画布，图例按视图/样本独立保存。v1 RNA sidecar 继续有效，v2
SpatialGLUE sidecar 增加输入模态、每模态预处理/特征摘要、配对 QC 和 GPU provenance。

仅共同存在且各模态非零的观测参加训练；缺失/全零点保留为 `Not analyzed`。四模态必须
显式选择包含 RNA 的两/三个支持模态，报告未使用的输入。标准化蛋白等没有已验证预处理
路径的输入不自动转换。技术校验不等同于组织学验证，域编号也不跨方法对齐。

任务并行数在部分代表样本测试后按实测资源和吞吐量决定，合计预算为 40 线程、128 GiB
主存和 64 GiB 显存，并至少保留 8 GiB 空闲显存。受管理并行任务继承全局和 GPU 锁租约；
CUDA 或资源不可用时明确失败，不退回 CPU。详见[SpatialGLUE 工作流](空间域识别.md#spatialglue-多模态空间域)。

本机 A800 的两个代表样本完成串行/双任务对照后，本次选用 2 个任务、每任务 8 线程。
吞吐量提升约 47%，域标签重放完全一致；联合表示在约定容差内一致，字节摘要并非逐位相同。
具体数据和范围见 [SpatialGLUE 接入记录](SpatialGLUE接入记录_2026-09-20.md)。

此前补充多规模测试完成 4 并发短测后曾暂停，历史证据见
[并行度测试记录](SpatialGLUE并行度测试_2026-09-20.md)。该旧配置不能作为下述准入扩展的最终结论。


### SpatialGLUE 非微生物准入与动态资源（2026-09-20）

准入以模态及来源数值语义选择配方，不再以 RNA counts 作为所有多模态的硬条件。
受体未检出和二元阴性不能统一当缺失删除；实际 187,619 细胞的 RNA/TCR/BCR 样本仅
238 个细胞双受体同时非零，非零交集会严重改变覆盖。少量蛋白特征不应压低其他模态维数。
四模态必须保留全部四个三模态结果及组合身份，不能由最后一次计算覆盖前面结果。

大规模资源预检须对应实际稀疏实现，不能继续使用上游稠密图的平方级内存估计。
先测各阶段峰值，再按规模、矩阵字节数、特征与边数校准；等待进程、CUDA 上下文和缓存
仍计入预算。上限提高为 80 核、768 GiB 主存，并按实时余量保留主存和至少 8 GiB 显存。
GPU 阶段与 CPU 阶段分配不同核心数，进程数与真正同时计算的任务数分别记录。
队列应在资源释放后自动补位；队首大任务等待时，可先填入能放下的小任务。
按规模分组学习实际峰值，使用 10% 的可变占用余量，避免固定启动开销导致大任务估算过高。
建图工作区固定为 128 MiB，不以扩大工作区作为本轮优化方向。
默认最多 80 项，实际并发由阶段资源准入控制；用户要求尽快收尾后取消追加实测，
因此 80 不是已验证的最优并发。69 万预热全程 RSS 峰值为 14.72 GiB，
PyTorch 保留显存峰值为 9.78 GiB；阶段结束保留量 3.57 GiB 不能代替峰值用于准入。

准入扩展阶段仅完成扩展及测试，未执行全量正式推断；该阶段状态和证据见
[准入扩展与调度测试](SpatialGLUE准入扩展与调度测试_2026-09-20.md)。

后续全量计算通过 `annotation/spatial_domain/gpu/run_full.sh start` 在后台运行，
`status --watch`／`logs` 监控，`stop` 停止，`resume` 续跑。每次运行冻结 catalogue、代码、
配置和组合清单，按资源自动补位；每 15 秒记录任务 PID、阶段、等待原因、CPU／主存／显存、
最近输出，逐任务保留完整日志。默认对未完成项追加一轮重试，再保留剩余清单供续跑。
续跑必须核对源摘要、参数、适配器、环境锁及产物完整性，20／120 epochs 的预热结果不能
替代完整训练结果。产物始终写入运行目录，计算脚本不自动发布或重启网站。详见
[SpatialGLUE 全量后台续跑](空间域识别.md#spatialglue-全量后台续跑)。

终端中的 `nvidia-smi` 正常不代表高频子进程查询每次都能在 10 秒内完成。全量启动时曾有
一次整卡查询及一次进程查询超时，旧调度器把监控错误升级为整轮失败，208 项均未完成。
GPU 监控现改为持有 NVML 句柄的单一后台采样线程；读取失败或数据超过 5 秒未更新时
只暂停新任务／新阶段准入，保留在运行任务和最后一次观测，恢复后继续。心跳必须明确记录
监控状态及采样年龄，不能用过期显存或缺失进程读数批准新资源，也不能将其当作零占用。
相同命令的六次复测均正常，未确认先前单次查询超时的底层原因；详细证据和续跑目录见
[GPU 监控修复记录](SpatialGLUE后台监控修复_2026-09-20.md)。

### SpatialGLUE 甲基化残差失败修复（2026-09-20）

`GSE270498_spatial_dmt_me11_replicate_50um` 的 canonical metadata 和 S032 接入报告均明确
标记为 signed MethSCAn residual，实测范围 −1.6054529316 至 1.4399391198。不能把所有
`methylation:normalized` 当作 0–1 比例，也不能通过截断、取绝对值或重新映射消除负值。
该已确认来源使用 `methylation_residual_v1`，保留符号及观测零值，只做标准化和 PCA；
报告写入来源语义及与比例切片不可数值比较的提示。其他来源仍执行比例范围校验，所有
输入仍要求有限数值。修复后通过新冻结目录的 `--dataset ID` 单独补算失败项，保留原批
已完成结果与仍在运行的大样本，避免适配器版本变化导致整批重算。

2026-09-21 已在 node3 用新冻结目录单独启动该组合的完整补算，残差配方和零值保留的
相关回归检查通过。用户最新决定仅计算、暂缓发布，自动发布包装脚本已禁用。
计算节点 node3 与网站节点 node1 不同，本机 `/healthz` 和 tmux 状态不能代替部署主机
的服务状态。运行路径和监控命令见[补算记录](SpatialGLUE残差补算_2026-09-21.md)。

SpatialGLUE 发布使用 `publish_completed.sh --method spatialglue --run-root <冻结目录>`，
需要先上线成功项时加 `--completed-only`。必须按 Database 和模态组合识别结果，不能沿用
RNA 的每个 Database 唯一 generation 假设。以冻结任务和组合 status 固定成功清单，校验
原运行代码摘要、环境锁、训练参数及源文件；当前修复后的适配器摘要不能用来否定旧批次
已经完成且来源一致的成功产物。合入 release 时保留已有 RNA 结果，逐组合验证页面和
点位接口，失败项延后；切换或启动验证失败沿用发布事务回滚。

### 分子分布与注释模式共用画布

Database 的 `Molecular distribution` 使用独立分子 sidecar，展示各模态 `X` 的存储值及
缺测状态，不属于细胞类型或空间域推断结果。它与注释模式按来源 sample ID 共用视角，
连续色带不使用注释分类码、confidence 或 ontology 语义；返回注释模式时保留原有分类
选择及 `Unannotated`/`Uncertain` 初始隐藏规则。准备、审计和发布使用普通 `iscdc` 环境，
见 [README 分子空间分布](../../README.md#分子空间分布) 和
[功能契约](../开发约束.md#molecular-visualization)。
