# isCDC 数据使用说明

本文面向通过 isCDC 网页、JSON API 或下载文件使用空间多组学数据的研究人员，说明目录中的
数据类别、`.h5mu` 文件结构、元数据字段、读取方法和分析时需要特别注意的语义。当前公开
文件遵循面向跨组学翻译的 isCDC schema 1.2。

## 1. 使用前先确认

1. `Database` 是一个 `dataset_type: full` 的全集文件；`Challenge` 是由相同 `split_id`
   的 `train` 和 `test` 文件组成的一次评估划分。不要把网页上的展示类别当作 `.h5mu`
   中新的数据集类型。
2. 下载数据时建议同时取得 `.h5mu`、`metadata.yaml`、`manifest.json`、
   `validation_report.json` 和 `checksum.sha256`。数据含义、许可、校验状态和文件完整性分散
   在这些文件中，仅下载 `.h5mu` 不足以完成可复现的数据使用记录。若详情页列出 WSI 等
   辅助文件，并且分析使用了它们，也应保存对应文件、来源 URL 和 SHA-256。
3. `X` 的数值语义由每个模态的 `uns["assay"]["value_type"]` 决定。不能默认所有矩阵都是
   原始 counts，也不能对已经归一化的矩阵重复归一化。
4. 两模态文件的 observation 完全配对；三个及以上模态的 `partially_shared` 文件可能存在
   缺失模态。此时请根据各模态 `obs_names` 和 mask 判断数据是否存在，不能把填充值当作
   真实测量值。
5. `cell_type` 是可选的 observation 级来源标签。`Unannotated` 表示公开来源未覆盖该
   observation，并可通过 `uns["cell_type_provenance"]` 核对来源文件与覆盖统计；它不是模型
   预测类别。列不存在表示本站没有确认可靠的来源标签，不表示所有细胞属于未知类型。
6. Database 页面上的 cell type 空间可视化可能来自既有来源标签，也可能来自独立的计算推断
   sidecar；它不是 `.h5mu` 中缺失 `cell_type` 的替代品，也不应作为 canonical annotation
   下载使用。
7. 目录不保存 dataset License 字段，不表示数据属于公共领域或可不受限制地使用。
   使用前必须核对 `source` 和原始发布页面的现行条款。

## 2. 浏览、检索与下载

### 2.1 网页和 API

| 用途 | 路径 |
| --- | --- |
| 浏览全集 Database | `/databases` |
| 查看一个全集 | `/databases/{dataset_id}` |
| 浏览训练/测试 Challenge | `/challenges` |
| 查看一个 Challenge | `/challenges/{split_id}` |
| 全集列表与详情 JSON | `/api/databases`、`/api/databases/{dataset_id}` |
| Challenge 列表与详情 JSON | `/api/challenges`、`/api/challenges/{split_id}` |
| 下载主数据及来源文件 | `/downloads/{dataset_id}/{kind}` |
| 下载辅助文件 | `/downloads/{dataset_id}/auxiliary/{auxiliary_id}` |
| 交互式 API 文档 | `/docs` |

列表支持 `q`、`organism`、`tissue`、`modality`、`technology` 和 `spatial_unit` 过滤；
Challenge 还支持 `challenge_type` 以及 `sort=newest|difficulty_asc|difficulty_desc`。JSON
列表使用 `limit` 和 `offset` 分页，`limit` 范围为 1–100。difficulty 排序先作用于全部筛选
结果，再进行分页；没有可用 difficulty 的 Challenge 在升序和降序中均位于末尾。

例如，读取 AUROC 最高的 20 个 Challenge：

```text
/api/challenges?sort=difficulty_desc&limit=20&offset=0
```

`newest` 是默认顺序。筛选参数可与 `sort`、`limit` 和 `offset` 同时使用。

Database 详情页在当前 source SHA 对应的 sidecar 通过启动校验时显示 cell type 空间可视化。
其点位端点是页面内部实现，不进入 OpenAPI，也不是公共、稳定的数据下载 API；研究分析仍应
以下载的 `.h5mu` 来源列或另行保存且完整记录 provenance 的推断产物为准。sidecar 缺失、
失败、损坏或过期时页面不会显示占位区域。

可视化标题旁的 `?` 按钮说明当前注释方法。若标签来自既有注释文件，弹窗会直接注明未进行
计算推断，且不显示推断专用信息；若标签为计算推断结果，弹窗会列出方法、reference ID/版本、
运行参数、QC 发布阈值和实际 QC 结果。`Not configured` 表示对应 QC gate 未配置，不表示 QC
失败。逐点 confidence 不在该方法弹窗重复展示，仍以点位 hover 为准。

图例中的精确类别 `Unannotated` 首次加载时默认不勾选，因此这些点位默认不显示；它仍保留在
图例中，用户可手动勾选或通过 `Select all` 显示。其他类别默认勾选，来源自身定义的
`Unlabeled` 等类别不受此规则影响。这只是浏览器初始展示状态，不会修改 `.h5mu`、sidecar
点位或下载内容。

Database 目录页和详情页会在存在对应资源时显示样本或切片缩略图；缺图条目不会显示占位
图像。缩略图仅用于辅助识别，不保证是 H&E，也不表示原始 WSI 已公开。缩略图本身不属于
`.h5mu` 必需内容，也不出现在 Database JSON API 中。若原始 WSI 已在本站注册，所属数据详情
页的下载面板会显示辅助文件按钮，JSON 的 `auxiliary_files` 也会给出本站下载 URL。
当辅助文件 ID 为 `he_wsi` 时，本站缩略图直接由该 WSI 的完整切片视图生成，保持纵横比且
最长边不超过 640 px；它仍只是有损 WebP 预览，不能代替原 WSI 做定量图像分析。没有按钮
或清单时不得从缩略图推断 WSI 可用。图像类型、来源与当前 WSI 入库状态以 Database 详情页
的辅助文件清单、source URL 和 SHA-256 为准。

过滤 Challenge 时，只要 train 或 test 一侧满足全部条件，响应就会返回该 Challenge
已经导入的完整两侧。这一行为用于保留评估划分的上下文，因此不能据此认定两侧分别都满足
过滤条件。

当某一侧由多个 source Databases 组成时，详情页 File metadata 的 Source 和 Derivation 的
Source databases 均按 sample 逐行显示；即使多个 sample 共用相同 Source，也不会合并。
Challenge JSON 在该侧的 `sample_sources` 返回 derived/original sample、source Database
ID/标题及该 Database 自身的 Source。full 和单来源文件的 `sample_sources` 为空列表。

### 2.2 Challenge difficulty 的含义

Challenge 目录和详情页显示以下三个派生指标：

| 指标 | 含义 |
| --- | --- |
| Domain AUROC | 固定 domain classifier 对 train/test 来源的 held-out 区分能力；越高表示在所用输入 representation 下越容易区分 |
| Shift score | `2 × (AUROC - 0.5)` 并截断至 0–1；0 表示接近不可区分，1 表示接近完全可区分 |
| Percentile | 当前成功评估 Challenge 中的全局相对位置；例如 76% 表示该 train/test shift 大于约 76% 的当前 Challenge |

网页中 Difficulty 标题旁的 `?` 可打开方法说明。该方法对 train/test 进行可复现的平衡采样，
仅使用共同且确认测量的输入特征，在 classifier training fold 内选择高方差特征、拟合固定
50 维 PCA 和 L2 logistic regression，并以 held-out prediction 计算 AUROC。目录发布的是离线
重复评估的 mean AUROC，而不是训练集准确率。

这些数值是 **train/test distribution separability proxy**，不是 Challenge 的绝对难度、真实
biological shift 或任何下游模型性能预测。技术平台、归一化流程、batch、donor 或 slice 边界
也可能造成高可分性；比较时应结合 `challenge_type` 和具体元数据解释。网站不使用固定
Easy/Medium/Hard 阈值。

当离线报告尚未生成、某一 Challenge 评估失败，或报告与当前目录文件不一致时，网页显示
`Unavailable`，API 的 `difficulty` 为 `null`。这不表示 train/test shift 为零。Percentile 会随
目录中的 Challenge 集合变化，因此用于论文或报告时应同时记录访问日期、AUROC 和 percentile，
不要只保存相对名次。

主文件下载路由中的 `kind` 可以是：

| `kind` | 下载内容 | 主要用途 |
| --- | --- | --- |
| `h5mu` | MuData 主文件 | 矩阵、观测、特征、空间坐标和文件内元数据 |
| `metadata` | 人工维护的 YAML | 标题、描述、关键词、许可、论文及目录元数据 |
| `manifest` | 导入清单 JSON | 文件大小、SHA-256、模态规模和导入时间 |
| `validation` | 校验报告 JSON | 有效状态、错误、警告和结构摘要 |
| `checksum` | SHA-256 文本 | 核对 `.h5mu` 下载完整性 |

辅助文件使用 manifest 中的稳定 `auxiliary_id`，而不是文件系统路径。例如 `he_wsi` 对应所属
数据文件的一张 H&E 全切片图像。辅助文件不会形成独立 Database 或 Challenge，也没有独立
详情页。大文件端点支持 HEAD、单段或多段 byte Range 和 `If-Range`，可用断点续传：

```bash
curl -fL -C - \
  -o <original-filename>.ome.tif \
  <base-url>/downloads/<dataset_id>/auxiliary/he_wsi
```

是否允许使用辅助文件必须通过所属数据集的 `source` 和辅助项的
`source_url` 到原始发布页面确认；不能把本站可下载等同于无限制使用。

### 2.3 完整性校验

详情 API、`manifest.json` 和 `checksum.sha256` 都提供 `.h5mu` 的 SHA-256。下载路由会把
主文件命名为 `{dataset_id}.h5mu`，而 checksum 文件中的原始存储名是 `dataset.h5mu`，因此
最稳妥的做法是直接计算下载文件的摘要，再与记录值比较：

```bash
sha256sum <dataset_id>.h5mu
```

摘要一致只能证明传输内容与目录中的文件一致；数据是否通过结构校验还应查看
`validation_report.json` 的 `valid`、`errors` 和 `warnings`。目录只收录通过校验的文件，
但通过校验的文件仍可能带有需要用户判断的警告。

辅助文件的字节数和 SHA-256 位于详情 API 的 `auxiliary_files` 以及 manifest 1.1 的
`auxiliary_files` 中，不写入只面向 `.h5mu` 的 `checksum.sha256`。下载后应对辅助文件单独运行
`sha256sum` 并与记录值比较。HTTP Range 只保证分段传输语义，不能替代最终的完整文件哈希。

## 3. `.h5mu` 文件结构

`.h5mu` 是 MuData 的 HDF5 文件。一个文件包含顶层 MuData 对象，以及至少两个以 AnnData
表示的生物组学模态。最小结构如下：

```text
MuData
├── obs
│   ├── index / obs_names                  全部观测对象的统一 ID
│   ├── sample_id                          样本或局部空间坐标系
│   ├── cell_type                          可选；完整存储的 observation 级来源标签
│   ├── source_dataset_id                  仅 train/test 必需
│   └── source_obs_id                      仅 train/test 必需
├── obsm
│   └── spatial                            N×2 [x,y] 或 N×3 [x,y,z]
├── uns
│   └── database                           数据集级元数据
└── mod
    ├── rna / protein / atac / ...         一个 AnnData 模态
    │   ├── X                              观测对象×特征矩阵
    │   ├── obs_names                      本模态拥有的观测 ID
    │   ├── var_names                      本模态特征 ID
    │   ├── uns["assay"]                   技术与数值语义
    │   ├── varm["feature_measured_by_source"]  条件性存在的测量 mask
    │   └── uns["feature_measurement"]     mask 的配套说明
    └── <其他模态>
```

组织图像、病理图像和细胞形态不是独立的组学模态。`layers`、`raw`、PCA、UMAP、聚类、QC
指标、图像和空间邻接图等内容允许存在，但不属于 schema 1.2 的必需结构，用户不应假定每个
文件都包含这些对象。顶层 `obs["cell_type"]` 是一个有条件验证的统一可选字段；其他细胞亚型、
聚类、实验分组以及各模态 `obs`、`var` 中的项目特异性列不属于统一字段，使用前应逐列检查
名称、类型、语义和缺失值。

### 3.1 顶层观测与模态行的对应关系

- `mdata.obs_names` 是文件内所有观测对象的唯一 ID 集合，并且等于所有模态
  `obs_names` 的并集。
- 每个模态的 `obs_names` 是顶层 ID 的子集。矩阵 `adata.X` 的第 `i` 行对应
  `adata.obs_names[i]`，不应直接假定它对应顶层 `mdata.obs.iloc[i]`。
- 若需要为某个模态取得空间坐标，应按 ID 显式对齐：

```python
positions = mdata.obs_names.get_indexer(adata.obs_names)
modality_spatial = mdata.obsm["spatial"][positions]
```

- `pairing_type: same_unit` 表示所有模态覆盖相同观测集合；`partially_shared` 仅允许用于
  三个及以上模态，表示模态间有部分重叠。schema 1.2 不收录 `unpaired` 数据。
- 两模态文件可以按 observation ID 一一对齐。对三个及以上模态的 `partially_shared` 数据
  开展指定模态对翻译时，必须取这两个模态的 ID 交集并显式处理其他缺失模态。

### 3.2 矩阵与特征

每个模态的 `X` 行为观测对象，列为生物学特征。`X` 可以采用稠密或稀疏存储；大型文件应
按需切片，避免直接把完整矩阵转换为 NumPy 稠密数组。

`var_names` 在模态内唯一，并用于稳定识别特征。常见约定为：

| 模态 | 推荐的特征 ID |
| --- | --- |
| `rna` | Ensembl ID 或 gene symbol |
| `protein` | 蛋白或抗体靶标名称 |
| `atac`、`histone` | `chr:start-end` |
| `methylation` | CpG ID 或基因组区间 |
| `metabolite` | HMDB ID 或标准化名称 |

跨文件合并时应按 `var_names` 对齐，不能只按列位置拼接。

### 3.3 空间坐标

`mdata.obsm["spatial"]` 的行数与顶层观测数相同，列顺序固定为二维 `[x, y]` 或三维
`[x, y, z]`。坐标的数值单位必须结合 `coordinate_unit` 解读：

- `micrometer`、`millimeter`：物理距离；
- `pixel`：图像像素坐标；
- `array_index`：平台原生的离散阵列索引，不是像素或物理距离。

`sample_id` 表示观测对象所属样本、切片或独立坐标系。不同 `sample_id` 的坐标默认是彼此
独立的局部坐标，不能仅因数值范围相近就叠加。若坐标经过平移、缩放、旋转、镜像或配准，
train/test 文件的 `processing_description` 应说明该变换；全集的项目特异性坐标说明可见
`additional_metadata` 或下载的 `metadata.yaml`。

### 3.4 可选 cell type

存在时，`mdata.obs["cell_type"]` 与顶层 `obs_names` 逐行对应，并完整覆盖文件内所有
observation。它以无序 pandas categorical 保存，不包含空值、空白标签、首尾空白或未使用
category。来源明确提供 `Unlabeled` 等类别时，该值仍是一个有效来源类别，不能擅自改成空值。

当公开来源只注释了经核验的 observation 子集时，其余行使用保留类别 `Unannotated`，且该值
固定为最后一个 category。此时 `mdata.uns["cell_type_provenance"]` 以直接来源 Database ID
为键，记录注释文件名、URL、SHA-256、ID/label 列及当前文件内 annotated/unannotated 数量。
空间切分后的数字会随子集重算；组合文件可含多个来源条目。若没有 `Unannotated`，则不会有该
provenance。`Unannotated` 仅说明来源缺失，不应被解释为新的生物学细胞类型。

该字段统一的是存储格式和对齐要求，不是跨研究的 cell ontology。不同数据集可能采用不同
粒度、命名体系或生物学定义；合并分析前应回到 `source` 和论文核对，不能仅凭字符串相同就
认定定义等价。列不存在时，不应使用聚类或其他模型输出冒充本站确认的来源标签。当前
catalogue 的逐数据集核验依据见 [cell type 来源核验记录](cell_type来源核验记录.md)。

Database 详情页可能另外显示独立的 cell type 空间可视化 sidecar。该 sidecar 可以来自上述
来源列，也可以是方法说明中标明为 SingleR/RCTD 的计算推断结果；推断结果包含 confidence，
并允许 `Mixed`/`Uncertain` 状态。它不属于 `.h5mu` schema，不会写回
`mdata.obs["cell_type"]`，也不能作为来源标签或 canonical metadata 使用。2026-08-18 批次
35 个 Database 的架构、方法、QC 与限制见 README 的
[Cell type 空间可视化](../README.md#cell-type-空间可视化)以及
[细胞类型注释经验总结](annotation/细胞类型注释经验总结.md)。2026-08-28 新增 ccRCC Database
的来源型 sidecar 含 690,322 个点位，其中 331,237 个 `Unannotated` 在网页上默认隐藏但可选。

## 4. `.h5mu` 内的数据集级元数据

这些字段位于 `mdata.uns["database"]`。其中 `source`、`organism` 和 `tissue` 可以是一个
字符串，也可以是去重后的字符串列表。

| 字段 | 类型/取值 | 含义和使用提示 |
| --- | --- | --- |
| `schema_version` | 固定为 `"1.2"` | `.h5mu` 结构版本；与 `manifest_version` 无关 |
| `dataset_id` | 唯一字符串 | 目录内文件标识，最长 128 字符；仅含字母、数字、点、下划线和连字符，并以字母或数字开头 |
| `dataset_type` | `full`、`train`、`test` | 全集或某次 Challenge 的训练/测试侧 |
| `source` | 字符串或字符串列表 | 原始数据来源，如 GEO、Zenodo、DOI、项目编号或官方页面；引用时应回到该来源核对 |
| `organism` | 字符串或字符串列表 | 物种 |
| `tissue` | 字符串或字符串列表 | 主要组织 |
| `spatial_unit` | 字符串 | 每一矩阵行代表的空间单位；推荐 `cell`、`nucleus`、`spot`、`bin`、`region` |
| `coordinate_unit` | 字符串 | `obsm["spatial"]` 的单位；推荐 `micrometer`、`millimeter`、`pixel`、`array_index` |
| `pairing_type` | `same_unit`、`partially_shared` | 两模态必须为 `same_unit`；三个及以上模态可部分共享 |
| `derivation` | 对象或空 | `train`/`test` 必需，`full` 不应包含非空值；见下一节 |

`database` 允许项目特异性扩展字段。例如疾病、基因组版本、发育阶段、组蛋白标记、bin
大小或坐标系说明。此类字段没有统一枚举；API 将其放入 `additional_metadata`，分析前应按
字段原值和来源文档解释。组蛋白修饰统一使用 `histone` 模态，具体标记通常记录在
`database.histone_mark`。

## 5. 模态元数据

每个 `mdata.mod[modality]` 都在 `uns["assay"]` 中包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `technology` | 字符串或字符串列表 | 产生该模态的实验或测量技术；组合数据可能列出多种技术 |
| `value_type` | 非空字符串 | `X` 中数值的语义 |

`technology` 采用平台/方法级受控词表：`Immunofluorescence`、`MISAR-seq`、`SPOTS`、
`STARmap PLUS`、`Spatial ATAC-RNA-seq`、`Spatial CUT&Tag-RNA-seq`、
`Spatial-CITE-seq`、`Stereo-CITE-seq`、`Visium CytAssist` 和 `Xenium`。厂商、模态、版本、
组蛋白标记与处理细节不属于 Technology 筛选维度；组蛋白标记使用
`database.histone_mark`。

推荐的 `value_type` 包括：

| 值 | 一般含义 |
| --- | --- |
| `counts` | 原始或接近原始的计数 |
| `binary` | 二值测量 |
| `intensity` | 信号强度 |
| `normalized` | 已归一化数值，具体处理需结合来源或处理说明 |
| `log_normalized` | 已进行对数归一化 |
| `background_corrected_intensity` | 已背景校正的强度 |
| `accessibility_score` | 染色质可及性得分 |
| `unknown` | 无法确认；使用前需要额外核查来源 |

推荐值描述的是共同词汇，不替代具体预处理记录。对任何不是 `counts` 的矩阵，尤其应先核对
`processing_description`、项目特异性元数据和原始数据来源。

## 6. train/test 衍生元数据

`dataset_type` 为 `train` 或 `test` 时，`mdata.uns["database"]["derivation"]` 必须包含以下
字段：

| 字段 | 类型/取值 | 含义 |
| --- | --- | --- |
| `construction_type` | `subset` 或 `composite` | 来自一个全集的子集，或由至少两个全集组合 |
| `source_dataset_ids` | 非空唯一字符串列表 | 直接来源的 `full` 数据集 ID；不能指向另一个 train/test |
| `split_id` | 非空字符串 | 一次训练/测试划分的标识；相同值的两侧组成一个 Challenge |
| `challenge_type` | 三种固定值之一 | Challenge 的评估边界，见下表 |
| `selection_description` | 非空字符串 | 观测对象、样本、切片、空间区域或分组的选择规则 |
| `feature_merge_policy` | 四种固定值之一 | 多来源特征空间的对齐方法，见下表 |
| `processing_description` | 非空字符串 | 特征筛选、数值转换、坐标变换及其他处理 |
| `reference_dataset_id` | 字符串或空 | 仅 `reference` 策略使用，且必须是来源全集之一 |
| `random_seed` | 整数或空 | 随机选择所用种子；非随机过程通常为空 |

Challenge 类型：

| `challenge_type` | 评估边界 |
| --- | --- |
| `same_slice` | 同一物理切片内部按空间区域或观测对象划分 |
| `cross_slice_same_subject` | 同一个体的不同物理切片分处 train/test |
| `cross_subject` | 按个体隔离；也包括生物学重复、不同条件或阶段的跨个体划分 |

特征合并策略：

| `feature_merge_policy` | 特征空间含义 |
| --- | --- |
| `preserve` | 保留来源全集的原始特征及顺序，通常用于单来源 `subset` |
| `intersection` | 只保留相关来源共同测量的特征 |
| `union` | 保留来源特征并集；必须用测量 mask 区分未测量和真实零 |
| `reference` | 对齐到 `reference_dataset_id` 的特征及顺序；缺失目标特征时需要 mask |

衍生文件的顶层 `obs` 还包含：

| 字段 | 含义 |
| --- | --- |
| `source_dataset_id` | 当前观测直接来自哪个 `full` 数据集 |
| `source_obs_id` | 该观测在来源全集中的原始 `obs_name` |

若来源具有合规的 `cell_type`，空间子集会按 observation 传播它。组合产物的某一侧只有在该侧
全部来源均具有完整合规标签时才保存该列；任一来源缺少标签时省略整列。因此同一个 Challenge
的 train/test 两侧理论上可能一侧有该列、另一侧没有，使用前应分别检查。

同一衍生文件中的 `(source_dataset_id, source_obs_id)` 二元组唯一。train 和 test 两侧也应
互不重叠，这是检查数据泄漏的主要标识。组合数据为避免 ID 冲突，顶层观测 ID 通常采用
`<source_dataset_id>::<source_obs_id>`；多来源衍生文件的样本 ID 必须采用
`<source_dataset_id>::<original_sample_id>`；应以来源列而不是拆分字符串来追踪原始对象。

### 6.1 未测量特征 mask

采用 `union`，或采用 `reference` 且某来源缺少目标特征时，每个受影响模态包含：

```python
adata.varm["feature_measured_by_source"]
adata.uns["feature_measurement"]
```

mask 的形状为“该模态特征数 × 来源全集数”，列顺序由
`adata.uns["feature_measurement"]["source_dataset_ids"]` 给出。`True` 表示该来源实际测量
了该特征，`False` 表示未测量。配套元数据字段为：

| 字段 | 含义 |
| --- | --- |
| `mask_key` | 固定指向 `feature_measured_by_source` |
| `source_dataset_ids` | mask 的列顺序 |
| `placeholder_value` | 当前为 `0` |
| `description` | mask 和占位值的文字说明 |

当 mask 为 `False` 时，`X` 中的零只是存储占位，绝不能解释为真实零表达、零信号或零可及
性。若某来源完全没有该模态，mask 可以保留该来源的全 `False` 列，但该来源不会因此获得
伪造的模态观测行。

## 7. `metadata.yaml` 字段

YAML 是网站展示元数据的主记录。`.h5mu` 内已有的 database、sample 和 assay 元数据必须在
YAML 中出现并保持一致；YAML 的 `database` 可以补充文件内没有的项目特异性字段。

### 7.1 顶层字段

| 字段 | 要求 | 含义 |
| --- | --- | --- |
| `database` | 必需对象 | 第 4 节字段；train/test 另含第 6 节的 `derivation` |
| `sample_ids` | 至少一个、非空且唯一 | `.h5mu` 顶层 `obs["sample_id"]` 的去重值集合 |
| `modalities` | 至少两个 | 以模态名为键，每项包含 `technology` 和 `value_type` |
| `title` | 1–300 字符 | 网页和 API 使用的人类可读标题 |
| `description` | 非空字符串 | 数据内容、范围和用途的简要科学描述 |
| `keywords` | 唯一字符串列表，可为空 | 检索和主题说明 |
| `publication` | 键必需；对象或 `null` | 相关论文信息，字段见下表 |

根级别不接受其他字段；需要增加项目特异性元数据时，应放在 `database` 中。

### 7.2 论文

| 对象 | 子字段 | 要求与含义 |
| --- | --- | --- |
| `publication` | `citation` | 可选，格式化引文 |
| `publication` | `doi` | 可选，DOI |
| `publication` | `url` | 可选，论文页面 |

`publication` 对象存在时，`citation`、`doi`、`url` 至少一个非空。目录没有确认论文时
对应值为 `null`，但仍应引用数据来源和 isCDC 数据集标识。Dataset metadata
不接受 `license`；使用条件必须到 `source` 指向的原始仓库或发布页面确认。

### 7.3 示例

```yaml
database:
  schema_version: "1.2"
  dataset_id: example_rna_protein
  dataset_type: full
  source: GSE000000
  organism: Homo sapiens
  tissue: kidney
  spatial_unit: cell
  coordinate_unit: micrometer
  pairing_type: same_unit
sample_ids:
  - sample_01
modalities:
  rna:
    technology: Xenium
    value_type: counts
  protein:
    technology: Xenium
    value_type: intensity
title: Example spatial RNA and protein dataset
description: Spatial RNA and protein measurements from one kidney sample.
keywords:
  - spatial transcriptomics
  - spatial proteomics
publication: null
```

## 8. API 和导入清单中的派生字段

Database 详情 API，以及 Challenge 响应中的 `train`、`test`，使用相同的数据文件记录：

| 字段 | 来源与含义 |
| --- | --- |
| `dataset_id`、`schema_version`、`dataset_type` | `database` 元数据 |
| `title`、`description`、`keywords` | `metadata.yaml` |
| `source`、`organism`、`tissue` | `database` 元数据，保留字符串或列表形式 |
| `spatial_unit`、`coordinate_unit`、`pairing_type` | `database` 元数据 |
| `derivation` | train/test 的完整衍生元数据；full 为 `null` |
| `sample_ids` | 文件中实际样本 ID 的去重集合 |
| `sample_sources` | 多来源 train/test 的逐 sample 来源映射，包含 `sample_id`、`source_sample_id`、`source_database_id`、`source_database_title` 和保留 scalar/list 类型的 `source`；其他文件为空列表 |
| `publication` | `metadata.yaml`；可能为 `null` |
| `additional_metadata` | `database` 中标准字段以外的项目特异性字段 |
| `n_obs` | 顶层观测对象数量，不等于每个模态的观测数 |
| `coordinate_dimensions` | 空间坐标列数，值为 2 或 3 |
| `modalities` | 模态记录列表；每项含 `name`、`technology`、`value_type`、`n_obs`、`n_vars` |
| `modality_count` | 由 `modalities` 派生的模态数量；大于 2 时网页显示单独标识 |
| `file_size` | `.h5mu` 文件字节数 |
| `sha256` | `.h5mu` 的 SHA-256 |
| `validation_warning_count` | 导入时校验警告数量；具体内容见校验报告 |
| `imported_at` | `YYYY-MM-DD` 导入日期，不是原始实验或数据生成日期 |
| `downloads` | `.h5mu`、metadata、manifest、validation 和 checksum 五类主文件 URL |
| `auxiliary_files` | 辅助文件列表；每项含 `id`、`label`、`filename`、`media_type`、`size`、`sha256`、`source_url` 和 `download_url`；没有可用辅助文件时为空列表 |

`source` 仍是文件级聚合元数据，`derivation.source_dataset_ids` 仍是直接来源 full ID 列表；
两者不会因 `sample_sources` 的加入而改变。需要解释多来源文件中某个 sample 的具体来源时，
应读取 `sample_sources`，不要依赖两个聚合列表的位置碰巧一致。

公开详情页、JSON API、catalogue 和可下载的 `metadata.yaml` 都不包含 dataset
`license`。catalogue 和导入清单仍保留完整导入时间，供排序和审计使用；网页和 JSON
仅公开日期。

canonical `cell_type` 不复制到 catalogue 数据库，也不出现在公共 JSON 字段或过滤条件中；
需要使用来源标签时必须下载 `.h5mu` 并读取顶层 `obs`。Database 页面可展示启动时严格校验的
独立 cell type sidecar，但其中的推断标签不是该字段，也没有稳定公共 API 契约。这避免把
不同来源或模型的分类体系误当成统一目录 facet。

Challenge 响应还包含：

| 字段 | 含义 |
| --- | --- |
| `split_id` | Challenge 标识 |
| `challenge_type` | 两侧一致的评估边界 |
| `status` | `complete`、`missing_train` 或 `missing_test` |
| `difficulty` | 可空的 distribution-shift 难度摘要；可用时包含下述三个浮点字段 |
| `train`、`test` | 对应的数据文件记录；未导入的一侧为 `null` |

`difficulty` 可用时的 JSON 结构如下：

```json
{
  "mean_auroc": 0.81,
  "domain_shift_score": 0.62,
  "difficulty_percentile": 76.0
}
```

网页和 API 只公开这三个核心字段。AUROC 标准差、重复评估、采样哈希、representation 参数、
warning 和层级混杂诊断属于离线 `challenge_difficulty.json` 报告，不属于 `.h5mu`、manifest
或 `catalog.db` schema。

新导入或注册过辅助文件的数据集使用 manifest 1.1；应用仍可读取没有
`auxiliary_files` 字段的 manifest 1.0。`manifest_version` 只描述清单格式，不表示 `.h5mu`
schema 版本。清单还记录 `imported_at`、`database`、`sample_ids`、`n_obs`、
`coordinate_dimensions`、各模态规模和主文件名。manifest 1.1 的辅助项结构为：

```json
{
  "id": "he_wsi",
  "name": "auxiliary/example.ome.tif",
  "label": "H&E whole-slide image (OME-TIFF)",
  "media_type": "image/tiff",
  "size": 1427110955,
  "sha256": "<64 lowercase hexadecimal characters>",
  "source_url": "https://example.org/example.ome.tif",
  "retrieved_at": "2026-08-12T05:30:02.792907+00:00"
}
```

API 使用 `filename` 返回 basename，并另外生成 `download_url`；manifest 使用受控相对路径
`name`，不提供可由客户端选择的服务器路径。应用启动时发现辅助文件；某一数据文件的清单
无效、文件缺失或大小不符时，整份辅助清单按 fail-open 原则隐藏，主目录和主文件下载继续
可用。

### 9.3 检查来源特异的特征测量状态

```python
import numpy as np
import mudata

mdata = mudata.read_h5mu("derived.h5mu", backed="r")
try:
    adata = mdata.mod["rna"]
    if "feature_measured_by_source" in adata.varm:
        measurement = adata.uns["feature_measurement"]
        source_ids = list(measurement["source_dataset_ids"])
        mask = np.asarray(adata.varm["feature_measured_by_source"], dtype=bool)

        top_positions = mdata.obs_names.get_indexer(adata.obs_names)
        row_sources = mdata.obs.iloc[top_positions]["source_dataset_id"].astype(str)
        source_to_column = {source_id: i for i, source_id in enumerate(source_ids)}

        # 第 0 行中每个特征是否由该观测的来源全集实际测量。
        first_row_measured = mask[:, source_to_column[row_sources.iloc[0]]]
finally:
    mdata.file.close()
```

### 9.4 PyTorch

仓库提供可选的 `iscdc.pytorch.H5MuDataset`。它按顶层 observation 惰性读取矩阵，并返回：

- `modalities`：各模态张量；
- `modality_masks`：该 observation 是否拥有该模态；
- `feature_masks`：各特征是否真实测量；
- `spatial`：空间坐标；
- `obs`：观测 ID、样本 ID、train/test 的来源 ID，以及通过 `obs_columns` 显式请求的
  `cell_type` 等现有顶层列。

缺失模态和未测量特征用零占位，但训练时必须同时使用对应 mask。只有输入和目标模态均存在
且所有特征均真实测量时，才适合使用返回纯 `(x, y)` 的
`iscdc.pytorch.H5MuPredictionDataset`。具体示例见仓库 `README.md` 的“使用 PyTorch 训练”。

使用 `DataLoader(num_workers > 0)` 时，运行环境必须允许 worker 使用本地 IPC socket 传递
队列和张量。在受限沙箱或容器中应仅放行本机进程间通信；这不要求开放外部网络。若环境不能
提供本地 IPC，可将 `num_workers` 设为 `0` 进行单进程读取，但这不能替代项目完整测试中对
多进程读取路径的验证。

## 10. 分析、引用与复现建议

- 先读 `metadata.yaml` 和 `validation_report.json`，再决定归一化、特征过滤、批次校正和
  空间分析策略。
- 任何模态整合都按观测 ID 对齐；任何跨文件特征整合都按特征 ID 对齐。
- 分样本进行需要统一坐标系的空间运算，除非元数据明确说明已完成配准。
- 对 Challenge 使用目录提供的 train/test 边界，并以来源二元组检查泄漏；不要根据测试集
  重新选择训练特征或调参。
- 将目录 difficulty 仅作为筛选和解释 train/test shift 的快速参考；不要据此推断具体预测模型
  的最终性能。引用该指标时同时报告 mean AUROC、percentile、访问日期和输入模态（当前默认
  为 RNA）。
- 对 `union` 或部分 `reference` 数据始终传播 feature mask。未测量占位零不得进入均值、
  差异分析、损失函数或评价指标。
- 使用 `cell_type` 前先确认列存在并记录其来源分类层级；跨数据集整合时显式保存映射规则，
  不要把字符串相同当作 ontology 等价，也不要用模型推断值回填缺失的来源标签。
- 保存并报告 `dataset_id`、`schema_version`、访问日期和 `.h5mu` 的 SHA-256。使用 Challenge
  时还应报告 `split_id`、`challenge_type` 以及 train/test 两个 `dataset_id`；使用辅助文件时
  另行报告其 `id`、原始文件名、`source_url` 和 SHA-256。
- 按 `source` 指向的原始发布页面现行条款使用数据；优先引用 `publication`，并同时引用
  `source` 中的数据资源。目录元数据不能替代原始研究的许可条款、实验方法和伦理说明。

更严格的生产和验证约束见[数据库存储规范 1.2](数据库存储规范_v1.2.md)。该规范主要面向
数据制作者；一般数据用户以本文、下载元数据和具体数据集的来源说明为准。
